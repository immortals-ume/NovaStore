# NovaStore - React & Node - Full ECommerce Site

### Technologies Used :

- HTML5 and CSS3: Semantic Elements, CSS Grid, Flexbox
- React: Components, Props, Events, Hooks, Router, Axios
- Redux: Store, Reducers, Actions
- Node & Express: Web API, Body Parser, File Upload, JWT
- MongoDB: Mongoose, Aggregation
- Development: ESLint, Babel, Git, Github,
- Deployment: Heroku
  
## Run Locally

Requires **Node.js 22+** and MongoDB (local install or Docker).

### 1. Clone and configure

```
$ git clone https://github.com/immortals-ume/node-react-ecommerce.git
$ cd node-react-ecommerce
$ cp .env.example .env      # then set JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
```

### 2. Start MongoDB

```
$ docker compose up -d mongo
```

### 3. Install, seed and run the API

```
$ npm install
$ npm run seed     # creates the admin from ADMIN_EMAIL/ADMIN_PASSWORD and the sample clothing catalog
$ npm run dev      # http://localhost:5001, restarts on backend changes
```

### 4. Run the frontend

```
# open new terminal
$ cd frontend
$ npm install
$ npm run dev      # http://localhost:3000, proxies /api and /uploads to :5001
```

`npm run build` writes `frontend/build`, which the API serves at http://localhost:5001.

### 5. Sign in

- Open http://localhost:3000/signin and use the admin credentials from `.env`
- Manage products at http://localhost:3000/products

## Frontend

React 19 + Material UI 9, built with Vite. Server state goes through TanStack Query (`src/api/hooks.js`);
auth, bag and toasts are React contexts in `src/context`. Pages live in `src/pages` (admin screens under `admin/`).
Light and dark themes follow the system setting, with a toggle in the header.

## Catalog

Products belong to a department (`women`, `men`, `kids`) and a clothing category
(tops, shirts, knitwear, outerwear, jeans, trousers, shorts, dresses, skirts, activewear), defined in
`backend/lib/catalog.js`. Dresses and skirts are offered in women and kids only. Adult sizes run XS–XXL; kids sizes
are by age. `npm run seed -- --reset-products` replaces the catalog with the 36 sample products in
`backend/scripts/catalogData.js`; their illustrations are generated by `node backend/scripts/generate-product-art.js`.

## Backend

| Command | What it does |
| --- | --- |
| `npm run dev` | API with auto-restart (native `node --watch`) |
| `npm start` | API for production |
| `npm test` | API tests (node:test + Supertest + in-memory MongoDB) |
| `npm run lint` | ESLint |
| `npm run seed` | Admin account and sample catalog |

Layout: `backend/routes` wires URLs to `controllers` (request handling and zod schemas),
`services` hold business rules (pricing, stock, PayPal), `models` are Mongoose schemas.

API notes:

- Errors are always JSON: `{ "message": "...", "details": [...] }`.
- `GET /api/products` accepts `department`, `category`, `size`, `minPrice`, `maxPrice`, `searchKeyword` (name or brand),
  `sortOrder` (`newest`, `lowest`, `highest`, `rating`), `page` and `pageSize`; totals come back in the
  `X-Total-Count` and `X-Page-Count` headers.
- `GET /api/products/catalog` returns departments, categories and sizes with live product counts.
- Order items carry a `size`, which must be one the product offers.
- Order prices, tax and shipping are computed by the server; client-sent prices are ignored.
- `PUT /api/orders/:id/pay` verifies the payment with PayPal when `PAYPAL_CLIENT_SECRET` is set.
- `PUT /api/orders/:id/deliver` (admin) marks a paid order delivered.
