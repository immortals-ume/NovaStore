# NovaStore — React & Node Clothing Store

[![CI](https://github.com/immortals-ume/NovaStore/actions/workflows/ci.yml/badge.svg)](https://github.com/immortals-ume/NovaStore/actions/workflows/ci.yml)

A full-stack e-commerce site for clothing: browse by department and category, pick a size, check out with PayPal,
and manage products and orders as an admin.

### Tech stack

- **Frontend:** React 19, Material UI 9, React Router, TanStack Query, Vite
- **Backend:** Node.js 22, Express 5, Mongoose 9, zod validation, JWT auth, Helmet, rate limiting
- **Database:** MongoDB 8 (Docker Compose for local development)
- **Payments & uploads:** PayPal, local disk or Amazon S3
- **Tooling:** ESLint (flat config), node:test + Supertest, GitHub Actions CI
- **Deployment:** Heroku (`Procfile`)

## Run Locally

Requires **Node.js 22+** and MongoDB (local install or Docker).

### 1. Clone and configure

```
$ git clone https://github.com/immortals-ume/NovaStore.git
$ cd NovaStore
$ cp .env.example .env      # then set JWT_SECRET, ADMIN_EMAIL, ADMIN_PASSWORD
```

### 2. Start MongoDB

```
$ docker compose up -d mongo
```

### 3. Install, seed and run the API

```
$ npm install
$ npm run seed     # creates the admin from ADMIN_EMAIL/ADMIN_PASSWORD and the sample clothing catalog
$ npm run dev      # http://localhost:5001, restarts on backend changes
```

### 4. Run the frontend

```
# open new terminal
$ cd frontend
$ npm install
$ npm run dev      # http://localhost:3000, proxies /api and /uploads to :5001
```

`npm run build` writes `frontend/build`, which the API serves at http://localhost:5001.

### 5. Sign in

- Open http://localhost:3000/signin and use the admin credentials from `.env`
- Manage products at http://localhost:3000/admin/products and orders at http://localhost:3000/admin/orders

## Frontend

React 19 + Material UI 9, built with Vite. Server state goes through TanStack Query (`src/api/hooks.js`);
auth, bag and toasts are React contexts in `src/context`. Pages live in `src/pages` (admin screens under `admin/`).
Light and dark themes follow the system setting, with a toggle in the header.

## Catalog

Products belong to a department (`women`, `men`, `kids`) and a clothing category
(tops, shirts, knitwear, outerwear, jeans, trousers, shorts, dresses, skirts, activewear), defined in
`backend/lib/catalog.js`. Dresses and skirts are offered in women and kids only. Adult sizes run XS–XXL; kids sizes
are by age. `npm run seed -- --reset-products` replaces the catalog with the 36 sample products in
`backend/scripts/catalogData.js`; their illustrations are generated by `node backend/scripts/generate-product-art.js`.

## Backend

| Command | What it does |
| --- | --- |
| `npm run dev` | API with auto-restart (native `node --watch`) |
| `npm start` | API for production |
| `npm test` | API tests (node:test + Supertest + in-memory MongoDB) |
| `npm run lint` | ESLint |
| `npm run seed` | Admin account and sample catalog |

Layout: `backend/routes` wires URLs to `controllers` (request handling and zod schemas),
`services` hold business rules (pricing, stock, PayPal), `models` are Mongoose schemas.

API notes:

- Errors are always JSON: `{ "message": "...", "details": [...] }`.
- `GET /api/products` accepts `department`, `category`, `size`, `minPrice`, `maxPrice`, `searchKeyword` (name or brand),
  `sortOrder` (`newest`, `lowest`, `highest`, `rating`), `page` and `pageSize`; totals come back in the
  `X-Total-Count` and `X-Page-Count` headers.
- `GET /api/products/catalog` returns departments, categories and sizes with live product counts.
- Order items carry a `size`, which must be one the product offers.
- Order prices, tax and shipping are computed by the server; client-sent prices are ignored.
- `PUT /api/orders/:id/pay` verifies the payment with PayPal when `PAYPAL_CLIENT_SECRET` is set.
- `PUT /api/orders/:id/deliver` (admin) marks a paid order delivered.

## AI shopping assistant

A chat button in the bottom-right corner opens **Nova**, a shopping assistant powered by Claude
(`claude-opus-5-5` by default). Shoppers can ask for products ("a warm jacket under $150"), sizes or
store policies; replies stream in and suggested products appear as clickable cards.

- **Turn it on:** set `ANTHROPIC_API_KEY` in `.env`. Without a key the chat button is hidden and
  `POST /api/assistant/chat` returns 503.
- **How it works:** `backend/services/assistant.js` gives Claude four read-only tools that query the real catalog
  (`search_products`, `get_product`, `list_catalog`, `recommend_products`). Claude cannot change carts, orders or
  accounts. Prices and stock always come from the database.
- **Settings:** `ASSISTANT_MODEL` changes the model; `ASSISTANT_RATE_LIMIT` caps messages per IP every 15 minutes
  (default 30). Each message is a paid Claude API call.
- **Safety:** if Claude declines a request, it is retried on Anthropic's recommended fallback model
  (`fallbacks: "default"`); if that also declines, the shopper sees a polite message.
- **API:** `GET /api/assistant/status` → `{ enabled }`; `POST /api/assistant/chat` with
  `{ messages: [{ role, content }] }` streams server-sent events: `text`, `reset`, `products`, `error`, `done`.

## Continuous integration

`.github/workflows/ci.yml` runs on every pull request and on pushes to `master`:

- **Backend:** `npm install`, `npm run lint`, `npm test` on Node 22
- **Frontend:** `npm install` and `npm run build` in `frontend/`

Lockfiles (`package-lock.json`) are not committed, so CI installs the latest versions allowed by the
ranges in `package.json`.
